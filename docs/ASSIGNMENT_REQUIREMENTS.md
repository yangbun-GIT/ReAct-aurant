# OSS 과제4 요구사항 정리

이 문서는 `OSS_work4.txt`의 과제 내용을 `ReAct-aurant` 구현자가 바로 참조할 수 있도록 정리한 요구사항 문서입니다.

## 과제 목표

수업 시간에 배운 Agentic Design Pattern을 활용해 사용자의 조건에 맞는 맛집 찾기 AI Agent를 구현합니다.

핵심은 LLM에게 단순히 "맛집 추천해줘"라고 묻는 것이 아니라, Agent가 다음 흐름을 직접 수행하도록 만드는 것입니다.

1. 사용자 요청 분석
2. 필요한 정보 수집
3. 도구 호출
4. 도구 결과를 Observation으로 수신
5. 조건에 맞는 후보 필터링
6. 필요 시 추가 도구 호출
7. 최종 추천 생성

## 필수 구현 항목

### 맛집 검색 도구

사용자의 입력 조건에 따라 맛집 정보를 조회할 수 있는 도구를 구현해야 합니다.

도구는 다음 조건을 고려할 수 있어야 합니다.

- 지역 기반 검색
  - 예: 전주 객사 근처 맛집, 서울 홍대 파스타 맛집
- 음식 종류 기반 검색
  - 예: 한식, 일식, 양식, 카페, 디저트
- 평점
- 리뷰 수
- 거리
- 가격대
- 날씨
- 사용자 음식 선호도

외부 API 사용은 가능하지만 필수는 아닙니다.
Kakao Local API, Naver Search API, Google Places API 등을 사용할 수 있으나, 외부 API 사용이 어렵다면 직접 만든 샘플 맛집 데이터셋을 사용해도 됩니다.

이 프로젝트의 기본 방향은 과제 재현성과 무료 실행을 위해 직접 만든 로컬 샘플 맛집 데이터셋을 사용하는 것입니다.

### MCP 서버

최소 2개 이상의 MCP 서버를 활용해야 합니다.

이 프로젝트에서는 다음 2개 서버를 기본 구조로 사용합니다.

1. `env_context_server.py`
   - 날씨 정보
   - 사용자 선호도
   - 단기 메모리
2. `gourmet_db_server.py`
   - 맛집 검색
   - 맛집 상세 조회
   - 후보 정렬

### Agentic Design Pattern

수업에서 배운 Agentic Design Pattern을 최소 2개 이상 적용해야 합니다.

ReAct Pattern은 필수입니다.

필수 적용:

- ReAct Pattern
  - `Thought -> Action -> Observation -> Final Answer` 구조로 맛집을 탐색하고 추천합니다.

추가 적용 후보:

- Plan-and-Solve Pattern
  - 사용자 요청을 지역 분석, 음식 종류 파악, 후보 검색, 기준별 비교, 최종 추천 단계로 분해합니다.
- Reflection Pattern
  - 추천 결과가 사용자 조건에 맞는지 스스로 검토하고 부족한 점을 보완합니다.
- Tool Use Pattern
  - 맛집 검색 도구, 거리 계산 도구, 평점 필터링 도구 등을 Agent가 직접 호출합니다.
- Memory Pattern
  - 사용자의 선호 음식, 가격대, 방문 목적 등을 기억하고 추천에 반영합니다.

이 프로젝트에서는 ReAct, Tool Use, Plan-and-Solve, Reflection, Memory를 모두 반영하는 것을 목표로 합니다.

## ReAct Agent Client 요구사항

Agent가 도구를 직접 호출하면서 최종 답변을 생성하는 실행 루프를 구현해야 합니다.

필수 흐름:

1. 사용자 요청 분석
2. 필요한 도구 선택
3. 맛집 검색 도구 호출
4. 검색 결과 Observation 수신
5. 조건에 맞는 후보 필터링
6. 필요 시 추가 도구 호출
7. 최종 추천 답변 생성

구현 시 `react_client.py`는 이 흐름이 로그 또는 Trace에 드러나도록 작성합니다.

## 에러 대응 및 예외 처리

다음 상황을 처리해야 합니다.

- 존재하지 않는 지역이 입력된 경우
- 검색 결과가 없는 경우
- 음식 종류가 너무 모호한 경우
- API 호출에 실패한 경우
- 사용자의 조건이 부족한 경우

오류를 단순 출력하고 종료하지 않습니다.
Agent가 오류를 Observation으로 받은 뒤 다음 중 하나를 수행하도록 구현합니다.

- 검색 조건 완화
- 대체 후보 제안
- mock 또는 로컬 데이터 fallback 사용
- 사용자에게 추가 조건 질문

## 필수 실행 테스트 시나리오

다음 프롬프트를 실행하고 단계별 도구 호출 로그 또는 Trace를 제출해야 합니다.

```text
전주 객사 근처에서 친구랑 저녁 먹기 좋은 맛집을 찾아줘. 너무 비싸지 않고, 리뷰가 좋은 곳 위주로 3곳 추천해줘.
```

실행 로그에는 다음 내용이 드러나야 합니다.

- Agent의 판단 과정
- 호출한 도구 이름
- 도구 입력값
- 도구 실행 결과
- 최종 추천 결과
